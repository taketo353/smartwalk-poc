# SmartWalk 1日PoC 実施手順

角間坂の1地点を模したデモで、同じ参考危険度が学生向け・大学向けの画面とAtomS3Rに反映されることを確認します。実働7時間を想定しています。仕様の背景は [設計書](../SmartWalk.md)、起動コマンドとAPIの入出力は [README](../README.md) を参照してください。

## 09:00–09:30　全員で準備

1. 各自の担当ブランチに切り替える。API担当はPCでサーバーを起動し、学生向けと大学向けの両画面にアクセスできることを確認する。
2. AtomS3R、USBデータケーブル、スマホ、デモ用画像、手元の温度センサを確認する。PC・スマホ・AtomS3RでLANを共有し、スマホからPCのアドレスを開く。
3. 温度はまずテスト値、画像は保存画像の手動ラベルを使う。地点IDは `kakuma-slope-01`。温度送信と判定取得は5秒間隔とし、温度送信が20秒止まったら判定不能にする。

## 09:30–12:00　担当ごとに進める

| 担当 | 作業順 |
| --- | --- |
| 実機 | Wi-Fi接続 → テスト値の送信 → 判定取得 → 本体LCDまたは外付けLEDの色を確認 |
| 画像 | 乾燥・湿潤・氷の保存画像を用意 → 手動ラベルを送信 → RSPNet-Sで画像1枚の推論を試す |
| API・判定 | 温度と画像ラベルの受信 → 判定結果の返却 → 履歴と観測途絶時の状態を確認 |
| Web | 両画面の更新 → スマホ表示 → テスト入力の表示と大学向け履歴を確認 |

11:30から合流する。画像担当がラベルを送り、実機担当がテスト温度を送る。両画面とAtomS3Rに同じ判定が出れば午前の作業は完了。実機が使えなければ `python demo.py` でPC側を先に確認する。

## 13:00–15:00　実測と画像推論をつなぐ

1. 路面温度センサの機種と接続方法を確認できたら、[ファームウェアの手順](../firmware/README.md) に沿って実測値を接続する。センサで測る範囲と撮影範囲をそろえる。
2. 推論が動く場合は [画像入力の手順](../vision/README.md) に沿ってモデル出力を送る。動作確認が済まなければ、保存画像と手動ラベルを使う。
3. 15:00にデモの構成を決める。実測値かテスト値か、モデル出力か手動入力かを画面と結果メモで確認する。

## 15:00–17:00　通し確認とデモ

| 入力・操作 | 期待する結果 |
| --- | --- |
| 乾燥、路面温度 +5℃ | 低リスク、緑 |
| 湿潤、路面温度 +1℃ | 注意、黄 |
| 氷、路面温度 −1℃ | 高リスク（凍結疑い）、赤 |
| 温度送信だけを止め、判定の取得を続ける | 最後の観測から20秒後、次の取得で判定不能、青 |
| 乾燥の画像と +5℃の送信に戻す | 低リスクに復帰し、大学向けの履歴に反映 |

各ケースでAPI・両画面・実機の結果を記録します。今回確認するのは観測から表示までの連動です。角間坂での凍結検出精度は現地で別途評価します。
