# SmartWalkCam（観測ノード）

レンピン本体（AtomS3R-CAM、MLX90640、SSD1306 OLED、ボタン）で動かすファームウェアです。路面温度と、カメラ画像の光の反射から推定した路面状態をAPIに送ります。どちらも学生向け画面（`/student`）と大学向け画面（`/admin`）にそのまま反映されます。返ってきた危険度はOLEDにも出します。

## 書き込み

1. Arduino IDE でレンピンと同じボード設定を選びます。PSRAM は `OPI PSRAM` を有効にします（カメラ画像の変換に使います）。
2. ライブラリはレンピンと同じ Adafruit_MLX90640、Adafruit_SSD1306、Adafruit_GFX です。
3. `config.example.h` を同じフォルダーに `config.local.h` としてコピーし、次を設定します。
   - `SMARTWALK_WIFI_SSID`、`SMARTWALK_WIFI_PASSWORD`:2.4 GHz の Wi-Fi
   - `SMARTWALK_API_URL`:APIを動かすPCのLANアドレス（例 `http://192.168.1.20:8000`）。APIは `python server.py --host 0.0.0.0` で起動します
   - `SMARTWALK_I2C_SDA`、`SMARTWALK_I2C_SCL`、`SMARTWALK_BUTTON_PIN`:レンピンのスケッチと同じピン番号
4. 書き込んでシリアルモニター（115200 bps）を開くと、`WiFi connected: http://...` と観測ノードのアドレスが表示されます。OLEDの最下段にも出ます。

カメラの初期化に失敗する場合は、シリアルに `Camera init failed` と出ます。そのときはレンピンのスケッチのカメラ設定（`camera_config_t`）をそのまま `initCamera()` に移してください。

## デモの流れ

0. タイルで校正しておきます（下記）。
1. 本体を路面（またはタイル）に向けます。OLEDに路面温度と、APIから返った危険度（`low` / `caution` / `high` / `unknown`）が出ます。
2. ボタンを押すと撮影し、すぐに路面状態と温度を送ります。シリアルモニターで `snap` と入力しても同じです。
3. 画像担当は `http://<観測ノードのIP>/snapshot.jpg` から画像を保存して分類します。

```sh
curl -o dry.jpg http://192.168.1.30/snapshot.jpg
```

## 光の反射による路面状態の推定

5秒ごとにカメラ画像の中央部を解析し、`POST /vision` に `label`（`dry` / `wet` / `ice` / `snow`）、`vision_source: "model"`、`image_source: "live"` で送ります。続けて路面温度を送るので、APIの判定（画像は氷かつ0℃以下なら高リスク、など）にすぐ使われます。

解析に使う特徴量:

| 特徴量 | 見ているもの |
| --- | --- |
| `brightness` | 平均の明るさ。濡れたアスファルトは暗く、雪は明るい |
| `highlight` | 白飛びに近い画素の割合。水や氷の膜は鏡のように光を返し（鏡面反射）、ぎらつきが出る |
| `texture` | 隣り合う画素の明るさの差（明るさで割った値）。水や氷の膜はアスファルトのざらつきをならす |
| `saturation` | 色の鮮やかさ。雪は白いので低い |

### 校正（デモ前に必ず行う）

照明や路面の材質で特徴量が変わるので、デモで使う乾燥・濡れ・氷のタイルで校正します。校正するとその状態の特徴量を記録し、以後は最も近い状態を答えます。記録は電源を切っても残ります。

1. カメラを乾燥したタイルに向け、ブラウザで `http://<観測ノードのIP>/calibrate?label=dry` を開きます（シリアルモニターで `cal dry` でも可）。
2. 濡れたタイルで `label=wet`、凍らせたタイルで `label=ice` を同じように開きます。雪を使う場合は `label=snow`。
3. `http://<観測ノードのIP>/reflection.json` で、いまの特徴量と判定結果を確認できます。やり直すときは `label=clear` で記録を消します。

校正しない場合は簡単なルールで判定します。ただし画像だけでは氷と水を見分けられないため、ぎらつくか滑らかな路面は `wet` と答え、`ice` は出しません。

### 照明の置き方

鏡面反射は、光源がカメラから見て路面の「鏡の位置」にあるときだけ見えます。カメラが斜め下を向くなら、タイルをはさんだ反対側の、カメラと同じくらいの高さにデスクライトを置きます。カメラのすぐ横から照らしても、反射光はカメラに戻りません。校正とデモは同じ照明の配置で行います。

### 画像担当との分担

RSPNet を使うPCも `POST /vision` に送るため、両方を同時に動かすと後から届いた方で上書きされます。RSPNet で判定するときは `config.local.h` の `SMARTWALK_SEND_VISION` を `0` にします。

## 表示と配信

OLEDの表示:

| 行 | 内容 |
| --- | --- |
| 1〜2 | `RISK` と危険度 |
| 3 | 路面温度（中央部の平均、カッコ内は最小〜最大） |
| 4 | 反射から推定した路面状態とAPI送信の結果 |
| 5 | 観測ノードのIPアドレス |

| URL | 内容 |
| --- | --- |
| `/snapshot.jpg` | ボタンで最後に撮った画像（640×480） |
| `/capture.jpg` | その場で撮った画像 |
| `/thermal.json` | 熱画像32×24（行ごとに並んだ768個の値）と中央部の平均・最小・最大 |
| `/reflection.json` | 反射の特徴量、判定結果、校正値 |
| `/calibrate?label=...` | いまの画像で校正（`dry` / `wet` / `ice` / `snow` / `clear`） |

路面温度として平均する範囲は `config.local.h` の `SMARTWALK_ROI_*` で変えられます。手で持つときは路面が視野の中央に来るように向けます。
