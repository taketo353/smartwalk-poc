# 観測端末の設計（実機担当）

角間坂の1地点に置く固定式の観測端末です。三脚の上の箱から斜め下の路面を見て、路面温度の分布と路面画像を取ります。このファイルには実機担当の設計と進捗だけを書きます。

## 方針

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| 設置方式 | 固定式（三脚） | 同じ地点の温度の推移を記録できる。APIの地点ID固定、地点ごとの管理画面と合う |
| 路面温度 | MLX90640（視野角55°×35°、32×24画素） | 1点ではなく温度分布を取れる。レンピンで使った手持ちの部品 |
| 路面画像 | AtomS3R-CAM（GC0308、0.3MP） | 熱画像と同じ箱に入れ、視野をそろえる。端末だけで撮影できる |
| 検証用の路面温度 | DS18B20を貼った基準板 | 非接触で測った値が正しいかを確かめる。運用ではなく検証用 |
| 首振り（パン・チルト） | 今回は作らない | 1週間では機構設計まで手が回らない。角度は手で合わせて固定し、首振りは今後の拡張とする |

## なぜ温度とカメラの両方が必要か

凍結して滑るには「路面温度が0℃以下」と「路面に水分がある」の両方がそろう必要がある。

- 熱画像は温度を測れるが、水・氷・アスファルトは放射率がどれも0.9以上と近く、水分の有無を見分けにくい。
- カメラは濡れ（テカり）や雪（白さ）を見分けられるが、透明な薄い氷は濡れと区別できない。

| 状況 | 温度だけ | 画像だけ | 両方 |
| --- | --- | --- | --- |
| −3℃、乾燥 | 高リスク（誤報） | 低リスク | 低リスク |
| −1℃、薄い氷 | 高リスク | 濡れ（見逃し） | 高リスク |
| +5℃、濡れ | 低リスク | 濡れ | 注意 |

## 構成

```text
三脚の上の箱
├─ AtomS3R-CAM（観測ノード）
│   ├─ 内蔵カメラ GC0308 … 路面画像
│   └─ Grove（I2C）── ハブ ─┬─ MLX90640 … 路面温度の分布
│                           ├─ 温湿度センサ … 気温・湿度・露点
│                           └─ OLED … 測定値・Wi-Fi・IPアドレスの表示
└─ フード（筒）… 雪・雨と周囲からの赤外線を防ぐ

三脚の脚
└─ AtomS3R（表示ノード）… LCDの色で現地警告
    └─ Grove ── DS18B20 … 視野内の基準板の温度
```

AtomS3R-CAMはGroveポートが1つだけなので、I2Cの機器を観測ノード、1-WireのDS18B20と警告表示を表示ノードに分ける。観測ノードのOLED（レンピンの基板に接続済み）は小さい単色表示なので、歩行者向けの警告ではなく、設置と調整のときの状態確認に使う。歩行者向けの警告は、色で示せる表示ノードのLCDが担う。表示ノードは既存の `SmartWalk/SmartWalk.ino` がそのまま使える。表示ノードは三脚の脚に付けて歩行者から見える位置にし、DS18B20のケーブルを短くする。

## 視野と設置寸法

MLX90640（55°×35°）とAtomS3R-CAMのカメラ（57.6°）は視野がほぼ同じなので、並べて同じ向きに付ければ熱画像と写真を重ねやすい。

高さ1mから俯角45°で路面を見る場合の目安。

| 項目 | 値 |
| --- | --- |
| 路面上の見える範囲（奥行き） | 手前 約0.5m 〜 奥 約1.9m |
| 視野の中心までの距離 | 約1.4m |
| 中心付近の1画素の大きさ | 約4cm |
| 基準板の大きさ | 15cm角以上（3×3画素以上に写るように） |

基準板はアルミ板の表面に黒いつや消しテープを貼り、裏にDS18B20を密着させる。金属のままだと放射率が低く、熱画像の温度が正しく出ない。熱画像では、基準板の画素と、すぐ隣の路面の画素の両方を記録する。

## 組み立ての注意

- 箱の前面を透明な板でふさがない。アクリルやガラスは赤外線を通さない。開口部はフードで守る。
- AtomS3R-CAMの発熱がMLX90640に届かないよう、箱の中で離すか仕切る。
- MLX90640はI2Cを400kHz以上で使う。電源電圧と、モジュールにプルアップ抵抗とレベル変換があるかを確認する。

## 筐体（新規製作）

回路はレンピンのもの（AtomS3R-CAM、MLX90640、I2Cハブの基板）を流用し、筐体だけを三脚設置用に新しく作る。

| 要件 | 内容 |
| --- | --- |
| センサ面 | MLX90640とカメラを同じ面に並べ、光軸を平行にする。前面は開口のままにし、透明な板でふさがない |
| 熱の分離 | AtomS3R-CAMとMLX90640の間に仕切りを入れる。MLX90640の背面に空気層を残す |
| フード | 視野を欠けさせないよう、光軸から上下左右に30°以上開いたラッパ型にする。上側だけの庇にする場合は、光軸から20°以上上向きにする |
| 三脚への取り付け | 底面の重心付近に1/4インチのナットを埋め込む。角度は雲台で調整する |
| ケーブルの出口 | USB-C給電と書き込み、温湿度センサ、接触式温度計のケーブルを下向きに出す。雨水が入りにくい |
| 温湿度センサ | 筐体の外、下側の日陰に、風が通るカバー付きで付ける。筐体内の熱を拾わないようにする |
| 保守 | ふたはネジ止めで開けられるようにする。即時観測のボタンを外から押せるようにし、USB端子に手が届くようにする |
| 材料 | 屋外ではPLAより熱と紫外線に強いPETGが望ましい。白は日射を吸収しにくい |

フードの角度は、MLX90640の視野（55°×35°）とカメラの視野（57.6°）の半分に余裕を足して決めた。

基板のボタンはレンピンで撮影用に使っていたもの。今回は、押すとその場で撮影と観測の送信を行う「即時観測」に使う。周期を待たずに画面が切り替わるので、デモで状態の変化を見せやすい。基板下部の6ピンコネクタは使わない。

## APIへの送り方

- 路面温度は、熱画像のうち路面の領域（基準板を除く）の平均値を `surface_temperature_c` として `POST /observations` に送る。
- 画像は観測ノードが `http://<観測ノードのIP>/capture.jpg` で配信し、画像担当のPCが取りに行く。

## 他担当への相談事項

このフォルダの外は変更しない。必要な変更は各担当に相談する。

- API・判定:気温、湿度、基準板の温度（`air_temperature_c`、`humidity_percent`、`reference_temperature_c`）も受け取って履歴に残せるか。現状は `surface_temperature_c` 以外を保存しない。
- 画像:USBカメラの代わりに、観測ノードのURLから画像を取得できるか。
