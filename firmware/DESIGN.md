# 観測端末の設計（実機担当）

角間坂の1地点に固定して置き、斜め下の路面を見て、路面温度の分布と路面画像を取る観測端末です。このファイルには実機担当の設計と進捗だけを書きます。

## 今回のPoCで作るもの

レンピンの本体（筐体と回路）をそのまま使い、ファームウェアだけを書き換える。デモでは本体を手で持って路面に向け、乾燥・湿潤・凍結の3枚を撮る。

| 項目 | 今回のPoC | 本来の設置形態（今後） |
| --- | --- | --- |
| 設置 | 手で持って路面に向ける | 三脚やポールに固定し、同じ地点を見続ける |
| 筐体 | レンピン本体を流用 | 雲台に付けられ、雪よけのフードを持つ筐体 |
| 路面温度 | MLX90640（視野角55°×35°、32×24画素）の中央部の平均 | 同じ |
| 路面画像 | AtomS3R-CAM（GC0308、0.3MP） | 同じ |
| 現地表示 | 本体のOLEDに危険度と路面温度を表示 | 歩行者から見える色付きの表示器 |
| 温湿度、接触式温度計 | 付けない | 露点からの霜の予測と、非接触温度の検証に使う |

固定式で同じ地点を見続けることがSmartWalkの前提。今回は時間の都合で、その状態を手で持って再現する。

## なぜ温度とカメラの両方が必要か

凍結して滑るには「路面温度が0℃以下」と「路面に水分がある」の両方がそろう必要がある。

- 熱画像は温度を測れるが、水・氷・アスファルトは放射率がどれも0.9以上と近く、水分の有無を見分けにくい。
- カメラは濡れ（テカり）や雪（白さ）を見分けられるが、透明な薄い氷は濡れと区別できない。

| 状況 | 温度だけ | 画像だけ | 両方 |
| --- | --- | --- | --- |
| −3℃、乾燥 | 高リスク（誤報） | 低リスク | 低リスク |
| −1℃、薄い氷 | 高リスク | 濡れ（見逃し） | 高リスク |
| +5℃、濡れ | 低リスク | 濡れ | 注意 |

## 光の反射による路面状態の推定

カメラ画像から、路面の光の返し方を数値にして路面状態を推定する。端末の中で計算し、結果を `POST /vision` に送るので、学生向け・大学向けの両画面にそのまま表示される。

- 乾いたアスファルトは表面が粗く、光を四方に散らす（拡散反射）。ざらつきが写り、ぎらつきは少ない。
- 水や氷の膜は表面を平らにし、光を一方向に強く返す（鏡面反射）。ぎらつきが増え、ざらつきが減り、拡散光が減るぶん全体は暗くなる。
- 雪は光をよく散らすので、明るく白い。

明るさ・ぎらつき・ざらつき・色の鮮やかさの4つを特徴量にし、デモで使うタイルで校正して、最も近い状態を答える。校正しない場合はルールで判定し、画像だけでは見分けられない氷は出さない（水と同じ `wet` にする）。氷か水かは、路面温度と合わせてAPI側が判定する。

限界:鏡面反射は光源が鏡の位置にあるときしか見えないため、照明の配置に左右される。屋外では太陽や街灯の位置で変わる。今後は偏光フィルタ（鏡面反射は偏光している）や、端末からの照明で条件をそろえる方法が考えられる。

画像担当のRSPNetも `POST /vision` に送るので、同時に使うと後から届いた方で上書きされる。どちらで判定するかはデモの前に決め、反射による判定は `SMARTWALK_SEND_VISION` で止められる。

## 構成

```text
レンピン本体
└─ AtomS3R-CAM（観測ノード）
    ├─ 内蔵カメラ GC0308 … 路面画像
    ├─ ボタン … 撮影と即時送信
    └─ I2C ─┬─ MLX90640 … 路面温度の分布
            └─ OLED（SSD1306）… 危険度・路面温度・IPアドレス
```

ファームウェアは [SmartWalkCam](SmartWalkCam/)。ライブラリはレンピンと同じもの（Adafruit_MLX90640、Adafruit_SSD1306、Adafruit_GFX、esp_camera）を使う。

MLX90640（55°×35°）とカメラ（57.6°）は視野がほぼ同じで、本体の中で同じ向きに並んでいるため、熱画像と写真を重ねやすい。

## APIとの受け渡し

- 路面温度は、熱画像の中央部（列8〜23、行6〜17）の平均値を `surface_temperature_c` として5秒ごとに `POST /observations` に送る。`temperature_source` は `sensor`。読み取れないときは `null`。
- 反射から推定した路面状態を、温度の直前に `POST /vision`（`vision_source: "model"`、`image_source: "live"`）で送る。
- 返ってきた `risk` をOLEDに表示する。
- 画像は観測ノードが配信し、画像担当が取りに行く。サーバ側の変更は不要。

| URL | 内容 |
| --- | --- |
| `http://<観測ノードのIP>/snapshot.jpg` | ボタンで最後に撮った画像 |
| `http://<観測ノードのIP>/capture.jpg` | その場で撮った画像 |
| `http://<観測ノードのIP>/thermal.json` | 熱画像（32×24）と中央部の平均・最小・最大 |
| `http://<観測ノードのIP>/reflection.json` | 反射の特徴量と判定結果 |

## 固定設置の設計メモ（今後）

高さ1mから俯角45°で路面を見る場合の目安。

| 項目 | 値 |
| --- | --- |
| 路面上の見える範囲（奥行き） | 手前 約0.5m 〜 奥 約1.9m |
| 中心付近の1画素の大きさ | 約4cm |
| 接触式温度計の基準板 | 15cm角以上（3×3画素以上に写るように）、表面は黒いつや消し |

- 前面を透明な板でふさがない。アクリルやガラスは赤外線を通さない。
- フードは光軸から上下左右に30°以上開いたラッパ型か、光軸から20°以上上向きの庇にし、視野を欠けさせない。
- AtomS3R-CAMの発熱がMLX90640に届かないよう仕切る。温湿度センサは筐体の外の日陰に置く。
- 三脚には底面に埋め込んだ1/4インチのナットで付け、角度は雲台で合わせる。
